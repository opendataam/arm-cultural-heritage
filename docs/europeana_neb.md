# Europeana и НЭБ: поиск, карточки и файлы

Добавлены два независимых конвейера для материалов об Армении и армянском народе:

- `scripts/extract_europeana_armenia.py` использует официальные Europeana Search API и Record API;
- `scripts/extract_neb_armenia.py` использует публичные страницы поиска и карточек НЭБ, не обращаясь к внутренним API;
- `scripts/download_source_assets.py` скачивает файлы из нормализованных Parquet-записей с манифестом и возобновлением.

Оба импортёра последовательно обращаются к источнику, ждут между запросами, повторяют временные ошибки с экспоненциальной задержкой и кэшируют ответы в каталоге результата. Повторный запуск с теми же параметрами не должен повторно обращаться к уже полученным карточкам.

## Europeana

### Механизм доступа

Официальные точки доступа:

- поиск: `https://api.europeana.eu/record/v2/search.json`;
- полная карточка: `https://api.europeana.eu/record/v2/{DATASET_ID}/{LOCAL_ID}.json`.

Для работы нужен собственный бесплатный ключ Europeana. Он передаётся только через переменную окружения и не записывается в отчёты, Parquet или кэш:

```bash
export EUROPEANA_API_KEY='ваш-ключ'
```

Публичный демонстрационный ключ `api2demo` подходит для маленькой проверки, но не должен использоваться для полной выгрузки проекта.

Пилот с ограничением в 100 кандидатов на каждый встроенный запрос:

```bash
python3 scripts/extract_europeana_armenia.py \
  --output-dir output/europeana \
  --max-records 100 \
  --delay 1
```

Если Europeana недоступна с текущего IP, добавьте указанный прокси:

```bash
python3 scripts/extract_europeana_armenia.py \
  --output-dir output/europeana \
  --max-records 100 \
  --proxy http://127.0.0.1:7070
```

Прямое соединение используется по умолчанию. Автоматического переключения маршрута нет: прокси задаётся явно, чтобы не отправлять трафик не по тому пути.

### Фильтрация и полнота

Встроенный поиск разбит на шесть относительно небольших запросов вместо одного тяжёлого многоязычного выражения:

1. `Armenia`, `Armenian`, `Armenians`;
2. французские и немецкие названия и демонимы;
3. `Հայաստան`, `հայերեն`, `հայկական`;
4. `Армения`, `армянский`, `армянская`, `армяне`;
5. `Yerevan`, `Erivan`, `Ереван`;
6. `Artsakh`, `Арцах`.

Для каждого запроса применяется курсорная пагинация, до 100 записей за поисковый запрос и профиль `rich`. Это предпочтительнее `start`, который предназначен только для первых 1000 результатов. Полная карточка запрашивается для потенциально релевантных записей. Поисковые и полные ответы сохраняются в `raw_json` без API-ключа.

Опциональные серверные ограничения:

- `--media` — только записи, у которых Europeana знает URL полного медиафайла;
- `--reusability open` — только материалы с открытым повторным использованием по классификации Europeana; также доступны `restricted` и `permission`.

Для наиболее полного **метаданного** корпуса не задавайте эти два фильтра. Для подготовки файловой выгрузки они сокращают число карточек:

```bash
python3 scripts/extract_europeana_armenia.py \
  --output-dir output/europeana_open \
  --max-records 100 \
  --media \
  --reusability open
```

`--max-records 0` снимает лимит отдельно для каждого встроенного запроса. Такой запуск может потребовать десятков тысяч обращений к Record API и должен выполняться только с собственным ключом и задержкой не менее одной секунды.

Встроенные запросы — стартовый высокоточный набор, а не гарантия исчерпывающего покрытия всех 10 296 терминов реестра. Для дополнительных городов, персон и учреждений повторяйте `--query` с нужными выражениями Europeana; наличие `--query` заменяет встроенный набор. Дубликаты ID в пределах одного запуска пропускаются.

Если термин найден источником только в поле, отсутствующем в кратком ответе, локальный matcher может не увидеть его в нормализованном тексте. Такая запись не отбрасывается, а попадает в `armenia_review.parquet` с `armenia_match_reasons=[source_query_only]`.

## НЭБ

### Механизм доступа

Используются только публичные страницы:

- поиск: `https://rusneb.ru/search/?q=...`;
- карточка: `https://rusneb.ru/catalog/{ID}/`.

Публичного документированного массового API для этого сценария найти не удалось. Поэтому парсер зависит от HTML НЭБ и должен быть повторно проверен при изменении вёрстки. Внутренние `/api/`, `/rest_api/`, AJAX и закрытые функции не используются.

Небольшой пилот только по открытым документам:

```bash
python3 scripts/extract_neb_armenia.py \
  --output-dir output/neb \
  --max-records-per-query 15 \
  --access open \
  --delay 3
```

По умолчанию собираются карточки независимо от доступа к электронной копии (`--access all`), а лимит равен 15 уникальным карточкам на запрос. Встроенные запросы включают русские, английские и армянские формы `Армения`, `армянский`, `армяне`, `Ереван`, `Арцах`, `Armenia`, `Armenian`, `Yerevan`, `Artsakh`, `Հայաստան`, `հայերեն`. Как и для Europeana, повторный `--query` заменяет встроенный набор.

Для всех результатов выбранных запросов используйте `--max-records-per-query 0`. Это снимает ограничение только на **метаданные**, а не разрешает массовое скачивание документов.

По умолчанию используется прямой российский маршрут без подмены соединения. Если НЭБ недоступна из текущей сети, нужно передать прокси с российским IP:

```bash
python3 scripts/extract_neb_armenia.py \
  --output-dir output/neb \
  --proxy http://адрес-российского-прокси:порт
```

При проверке прямое соединение с НЭБ работало, а текущий `127.0.0.1:7070` возвращал 403, поэтому один и тот же прокси не следует без проверки назначать обоим источникам.

### Что извлекается из карточки

Из публичной карточки извлекаются:

- код документа НЭБ и канонический URL;
- заглавие, авторы, место и год издания, язык, каталог;
- библиографическое описание, тематика и другие доступные детальные поля;
- библиотека-источник;
- явно опубликованные ссылки на скачиваемые документы, с дедупликацией по формату.

`raw_json` содержит извлечённые исходные поля и meta-описание. Исходный HTML остаётся в `cache/` для аудита и повторного запуска. Ссылки на скачивание кодируются корректно, включая кириллицу и пробелы.

НЭБ сначала ищет по библиографии, а при отсутствии результата может искать по полному тексту. Если совпадение не видно в карточке, запись сохраняется как `review` с причиной `source_query_only`, а не ошибочно считается нерелевантной.

### Ограничение на файлы НЭБ

Пункт 5(д) [пользовательского соглашения НЭБ](https://rusneb.ru/user-agreement/) запрещает массовое автоматизированное скачивание объектов НЭБ. Поэтому:

- сбор метаданных и ссылок отделён от скачивания;
- для НЭБ `--max-files` обязателен, чтобы каждый файловый запуск был явно ограничен;
- скачиваются только записи с явной публичной ссылкой на открытый документ;
- закрытые документы и материалы ЭЧЗ не скачиваются;
- массовую файловую выгрузку нельзя запускать без согласования с оператором НЭБ.

Открытость скачивания не является лицензией на републикацию. Права на каждый объект нужно проверять отдельно.

## Скачивание файлов

Входом служит `armenia_records.parquet` или, после ручной проверки, `armenia_review.parquet`. Каждый файл записывается сначала во временный `.part`, затем атомарно переименовывается. Манифест содержит связь с записью, исходный URL, путь, MIME-тип, размер и SHA-256. Уже полностью скачанные файлы пропускаются.

Europeana, ограниченный пилот:

```bash
python3 scripts/download_source_assets.py \
  --input output/europeana_open/armenia_records.parquet \
  --output-dir output/europeana_files \
  --source europeana \
  --max-files 100
```

Без `--max-files` загрузчик обрабатывает все подходящие ссылки во входном Parquet. По умолчанию пропускаются записи без открытого rights statement. Разрешены Public Domain/CC0, CC BY, CC BY-SA и No Copyright. `--include-restricted` отключает этот фильтр, но не даёт юридического права на использование файла.

НЭБ, один явно выбранный открытый документ:

```bash
python3 scripts/download_source_assets.py \
  --input output/neb/armenia_records.parquet \
  --output-dir output/neb_files \
  --source neb \
  --max-files 1 \
  --delay 3
```

Если файл размещён у внешнего провайдера Europeana, его доступность и ограничения определяются этим провайдером. Ошибка скачивания не удаляет карточку и не приравнивается к удалению объекта: она сохраняется в манифесте и `asset_download_report.json`, а команда завершается с ненулевым кодом.

## Результаты и схема

Каждый импортёр создаёт:

| Файл | Содержимое |
| --- | --- |
| `armenia_records.parquet` | Подтверждённые strong-совпадения в нормализованных полях |
| `armenia_review.parquet` | Контекстные и query-only кандидаты |
| `audit_sample.csv` | Детерминированная выборка include/review/exclude |
| `report.json` | Запросы, лимиты, счётчики, сетевые обращения, ошибки и пути результатов |
| `errors.jsonl` | Ошибки получения отдельных карточек, если они были |
| `cache/` | Ответы для возобновления без повторных запросов |

Общая схема Parquet:

- `id`, `source`, `record_url`, `retrieved_at`, `source_queries`;
- `title`, `description`, `authors`, `date`, `places`, `subjects`, `languages`;
- `type`, `provider`, `rights`, `access`;
- `assets`: список структур `url`, `role`, `mime_type`, `expected_bytes`;
- `raw_json`;
- девять полей `armenia_*` с решением, силой, терминами, формами, полями и причинами совпадения — такими же, как у Goskatalog.

`include` означает наличие сильного доказательства в извлечённых метаданных, а не экспертную атрибуцию произведения. `review` не должен автоматически попадать на сайт как подтверждённый материал.
