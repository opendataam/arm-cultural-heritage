# MVP портала «Армянское культурное наследие»

Прототип портала по [техническому заданию](tz-heritage-portal.md). Он работает на данных четырёх источников: Госкаталога Музейного фонда РФ, отобранных классификатором проекта (`output/goskatalog/armenia_records.parquet`), памятников Армении из Викиданных, армянской периодики цифровой библиотеки BULAC BiNA и Указателя армянских рукописей (IArM). Цель — проверить на реальных данных связку из конвейера агрегации, поиска, карточек объектов, многоязычного интерфейса и API.

## Запуск

Нужен Python 3.11 или новее.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-portal.txt
.venv/bin/python -m portal.pipeline run
.venv/bin/uvicorn portal.web.app:app --port 8000
```

Сайт открывается по адресу <http://127.0.0.1:8000/>, документация API — <http://127.0.0.1:8000/docs>.

Конвейер собирает данные примерно за 1–2 минуты. Результаты он пишет в `build/portal/`: снимки источников, промежуточные записи, базу `portal.sqlite`, выгрузки и `report.json`. Каталог задаётся переменной `PORTAL_BUILD_DIR`, путь к базе — `PORTAL_DB`.

Стадии можно запускать по отдельности: `collect`, `transform`, `publish`. Ключ `--source` ограничивает сбор одним источником. Ключ `--force` публикует данные, даже если критическая проверка не прошла.

Тесты:

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

Оркестрация в Dagster:

```bash
.venv/bin/pip install -r requirements-orchestration.txt
.venv/bin/dagster dev -m portal.orchestration.definitions
```

## Сбор данных

Госкаталог обрабатывается экстрактором `scripts/extract_goskatalog_armenia.py`. Остальные источники собирают харвестеры, которые пишут `output/<источник>/records.parquet` и `report.json`:

```bash
python3 scripts/harvest_wikidata.py --limit 3000
python3 scripts/harvest_bina.py
python3 scripts/harvest_iarm.py
.venv/bin/python -m portal.pipeline run
```

Харвестеры представляются собственным User-Agent, делают запросы последовательно с паузой и повторяют их после отказов `429`, `5xx` и `maxlag`. Профильные источники публикуются целиком: matcher проекта для них не отбирает записи, а связывает их с сущностями реестра терминов. Каждая запись хранит свои права (`rights`), лицензию метаданных и строку атрибуции (`metadata_rights`) и подпись к изображению (`media_credit`). Условия использования источников описаны в [`data/sources.csv`](../data/sources.csv).

Записи-кандидаты (`armenia_review.parquet`) не публикуются, как требует раздел 6.3 ТЗ. Их число попадает в отчёт о прогоне.

## Что реализовано

| Требование | Раздел ТЗ | Реализация в MVP |
| --- | --- | --- |
| Реестр источников | 6.1 | `config/sources.toml`. Источник подключается записью в реестре и коннектором в `portal/pipeline/` |
| Конвейер | 6.3 | `portal/pipeline/stages.py`. Сбор сохраняет неизменяемый снимок с SHA-256. Дальше идут преобразование, нормализация, релевантность, связи с сущностями, уровни качества и публикация. Отчёт о прогоне пишется в `build/portal/report.json` |
| Проверка качества перед публикацией | 5.5, п. 7 | Если объём источника упал более чем на 30%, публикация блокируется и действующая база не заменяется |
| Оркестрация | 5.5 | `portal/orchestration/definitions.py` — тонкий слой Dagster над функциями конвейера. Каждый источник — отдельная партиция со своим расписанием. Есть повторы с экспоненциальной задержкой, блокирующая проверка объёма, сенсор сбоев (вебхук `PORTAL_ALERT_WEBHOOK`) и автоматическая публикация после обновления источников |
| Модель данных | 6.4 | Запись совместима с EDM: идентификаторы, название с языковой меткой, тип материала, поставщик и держатель, права, ссылка на источник, релевантность, происхождение записи |
| Нормализация | 6.5 | Даты переводятся в EDTF с интервалом лет: годы, диапазоны, десятилетия, века и их части, тысячелетия, даты до н. э. Структурные даты Госкаталога с заглушками (2099, +198900) отбрасываются. Создатели разделены на имя и роль. Из названий учреждений убрана организационно-правовая форма. Права — «Права не определены» (RightsStatements.org CNE) |
| Релевантность | 6.6 | Используются решения и объяснения сопоставителя проекта. Критерии creator, place, subject, language и holding выводятся из полей с совпадениями |
| Сущности | 6.7 | Словарь строится из `data/terms.csv`. Для 41 частой сущности добавлены названия на пяти языках (`config/entity_labels.toml`) |
| Уровни качества | 6.9 | Уровень содержания 0 или 1: разрешение изображений пока не измеряется. Уровень метаданных A–C — по предварительной методике. Записи с изображением ранжируются выше |
| Манифесты IIIF | 6.10, п. 2 | Presentation 3.0 для каждой записи с изображениями, в том числе для внешних изображений без собственного манифеста |
| Поиск | 7.4, 8.3, 8.5 | Полнотекстовый поиск со стеммингом русского, армянского и английского. Регистр, «ё», лигатура «և» и написания «եւ»/«եվ» не различаются. Поддерживаются фразы в кавычках, исключение `-слово`, `OR` и маска `*`. Запрос на любом языке раскрывается через названия сущностей: «Yerevan», «Երևան» и «Ереван» дают одну выдачу. Есть фасеты, фильтр по годам с гистограммой по векам, сортировки и автодополнение. Всё состояние поиска хранится в URL |
| Карточка объекта | 7.5 | Просмотрщик OpenSeadragon, группы метаданных, сущности, права, переход к источнику, манифест IIIF, EDM, цитирование и постоянная ссылка. Показаны также происхождение записи, объяснение релевантности, похожие объекты и разметка schema.org |
| Страницы сущностей, коллекций и учреждений | 7.7, 7.8, 7.11 | Заголовок и встроенная выдача с фасетами. Коллекции — сохранённые запросы в `config/collections.toml` |
| Многоязычность | 8.1, 8.2 | Пять обязательных языков: hy, ru, en, fr, es. Язык указан в URL. Выбор языка запоминается в cookie, при первом визите берётся из `Accept-Language`. Переключатель оставляет пользователя на той же странице. Множественные формы следуют правилам CLDR, числа форматируются по локали. Текст на языке источника помечается атрибутом `lang` |
| API и открытые данные | 10 | REST `/api/v1` с описанием OpenAPI: поиск с фасетами, записи (`format=json`, `edm`, `schema`), сущности, автодополнение, учреждения, статистика и отчёт о прогоне. Манифесты IIIF доступны по `/iiif/3/{id}/manifest`, выгрузки JSON Lines и Parquet — в `/dumps/` |

## Отступления от рекомендованного стека

Раздел 5.3 ТЗ допускает альтернативы с обоснованием. Для прототипа выбраны компоненты, которые не требуют отдельных серверов.

| ТЗ | MVP | Причина |
| --- | --- | --- |
| PostgreSQL и OpenSearch | Один файл SQLite: записи, индекс FTS5, фасеты. Подсчёт фасетов и сортировка выполняются в памяти процесса | Корпус из 58 тыс. записей укладывается в 15–200 мс на запрос без инфраструктуры. Хранилище скрыто за `portal/search.py` и `portal/store.py` |
| Nuxt 3 с серверным рендерингом | FastAPI и шаблоны Jinja2, тоже серверный рендеринг | Один язык и один процесс. URL совпадают с требованиями 7.1 |
| Сайт получает данные только через API (5.1, п. 1) | Сайт и API вызывают общий сервисный слой в одном процессе | Упрощение прототипа. Разделение — при переходе на целевой стек |
| Cantaloupe, локальные копии изображений | Изображения загружаются напрямую с goskatalog.ru | Правовой статус изображений не определён. Обработка медиа (6.10) не входила в прототип |
| Headless CMS и Weblate | Строки интерфейса в `portal/web/locales/*.json`, коллекции в TOML | Редакционного контента в прототипе нет |

## Ограничения

- Изображения показываются с сервера goskatalog.ru. Из некоторых сетей он недоступен: при проверке прототипа из Германии вместо изображений показывались заглушки и пояснение.
- Метаданные показаны на языке источника. Только у памятников из Викиданных название и описание выбираются на языке интерфейса. Машинного перевода нет.
- Переводы интерфейса на армянский, французский и испанский сделаны разработчиком без проверки носителями. По разделу 8.6 ТЗ перед запуском их должны проверить носители языков.
- Западноармянского языка (`hyw`) нет.
- Связи с сущностями найдены автоматически и не проверены. У части сущностей из реестра есть только русские названия.
- Размер изображений не измеряется. Поэтому уровень содержания не выше 1, а холсты в манифестах IIIF имеют условный размер 1000×1000.
- Транслитерация работает только через варианты названий сущностей. Общей транслитерации запросов (латиница, кириллица, армянское письмо) нет.
- Постраничная навигация ограничена 10 000 результатов. Курсорной пагинации API пока нет.
- Нет административной части, очереди проверки, CMS, личного кабинета, OAI-PMH, карты и шкалы времени, лимитов и ключей API.
- База занимает около 350 МБ, процесс сайта — около 110 МБ памяти. Первый запрос после запуска обрабатывается около 4 с.
