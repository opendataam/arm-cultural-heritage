# Структура `data/terms.csv`

`data/terms.csv` — основной реестр поисковых терминов и aliases. Он заменяет ручное редактирование отдельных языковых CSV и хранит как сами значения, так и правила их использования.

Машинно-читаемая схема строки находится в [`schema/terms.schema.json`](../schema/terms.schema.json). Она использует JSON Schema 2020-12 и применяется к объекту, полученному из одной CSV-строки. Поле `x-csv.columns` дополнительно фиксирует порядок колонок.

## Формат файла

- Кодировка: UTF-8.
- Разделитель: запятая.
- Заголовок: обязателен и должен точно соответствовать порядку ниже.
- Значения с запятыми заключаются в двойные кавычки по правилам CSV.
- Все колонки обязательны, но `pattern` и `negative_pattern` могут быть пустыми строками.
- Генерируемые файлы используют LF. Начальные и конечные пробелы значений удаляются при чтении.

```csv
entity_id,value,lang,script,category,pattern,match_strength,negative_pattern,source,review_status
```

## Колонки

| Колонка | Обязательное значение | Назначение |
| --- | --- | --- |
| `entity_id` | Непустой ID | Объединяет варианты одной сущности |
| `value` | Непустая строка | Отображаемый термин или alias |
| `lang` | Код `[a-z]{2,3}` | Язык значения |
| `script` | `Cyrl`, `Latn`, `Armn`, `Arab`, `Other` | Система письма |
| `category` | Одна из категорий ниже | Тип термина или сущности |
| `pattern` | Regex или пустая строка | Правило словоформ и вариантов |
| `match_strength` | `strong`, `context_only`, `weak` | Сила доказательства |
| `negative_pattern` | Regex или пустая строка | Локальный отрицательный контекст |
| `source` | Непустая строка | Происхождение записи |
| `review_status` | `approved`, `unverified`, `rejected` | Статус проверки |

### `entity_id`

Это внутренний стабильный идентификатор, а не Wikidata, VIAF или другой внешний authority ID. Один ID должен быть у всех aliases одной сущности:

```text
place.yerevan → Ереван, Yerevan, Erivan, Երևան
person.komitas → Комитас, Komitas, Կոմիտաս
```

Разные сущности не объединяются только из-за похожего написания. Например, персональное имя, фамилия и топоним могут иметь разные ID даже при одинаковом `value`.

Допустимый формат ID определяется схемой: латинские буквы и цифры, точка, подчёркивание, двоеточие и дефис. Пробелы не используются.

### `value`

Видимая форма термина. Она может быть словом, полным именем, названием учреждения или фразой. Для активных записей не допускаются дубликаты в пределах одного `(lang, category, normalized value)`.

При сопоставлении применяются:

- Unicode NFKC;
- case folding;
- замена `ё` на `е`;
- унификация видов тире;
- сворачивание повторных пробелов.

Исходное `value` при этом сохраняется без изменений.

### `lang` и `script`

`lang` описывает язык, а `script` — конкретное написание. Они не обязаны соответствовать самой распространённой паре языка и алфавита: армянская транслитерация латиницей может иметь `lang=hy`, `script=Latn`.

Для армянского используется `hy`; `am` относится к амхарскому и не применяется.

### `category`

| Категория | Содержимое |
| --- | --- |
| `keyword` | Демонимы, общие понятия и прочие ключевые слова |
| `geoname` | Страны, города, регионы, исторические места и географические объекты |
| `person` | Полные имена и однозначные aliases конкретных людей |
| `institution` | Музеи, библиотеки, организации, издательства и учреждения |
| `event` | Исторические события |
| `language` | Языки, письменности и языковые разновидности |
| `religion` | Церкви, религиозные организации и характерные понятия |
| `object` | Типы объектов культурного наследия |
| `dynasty` | Династии и роды |
| `name` | Отдельные личные имена — слабый признак |
| `surname` | Отдельные фамилии — слабый признак |
| `midname` | Отчества — слабый признак |

Категория не заменяет `match_strength`: например, полное имя персоны может быть `strong`, а фамилия того же человека — `context_only` или `weak`.

### `pattern`

Необязательный regex для словоформ и вариантов. Если поле пустое, matcher экранирует `value` и ищет его литерально; пробелы в литеральных фразах допускают вариативные пробельные последовательности.

Пример:

```csv
place.armenia,армения,ru,Cyrl,geoname,армени(?:я|и|е|й|ю|ей|ею),strong,,manual/curated-v2,approved
```

Ограничения:

- применяются Unicode-aware границы слов;
- regex нормализуется тем же способом, что и текст;
- разрешены только незахватывающие группы `(?:...)`;
- обычные захватывающие группы `(...)` запрещены, поскольку предфильтр DuckDB использует собственную группу извлечения;
- не используются неограниченные корни вроде `армен` или `ван`;
- агрессивное нечёткое сопоставление не выполняется.

Перед записью реестр компилирует все regex и сообщает об ошибках.

### `match_strength`

| Значение | Участие в поиске | Решение matcher |
| --- | --- | --- |
| `strong` | Активный предфильтр и точный поиск | `include` при совпадении в content-полях |
| `context_only` | Активный предфильтр и точный поиск | `review`, если нет независимого strong-доказательства |
| `weak` | Вспомогательный token-set | Никогда не даёт самостоятельного `include` |

Совпадение только в `museum.name` всегда требует `review`, даже если термин `strong`.

Слабые имена и фамилии не сканируются отдельно по всему корпусу. Они анализируются у кандидатов, найденных активными правилами, чтобы не создавать миллионы необоснованных совпадений.

### `negative_pattern`

Regex отрицательного контекста для неоднозначной сущности. Например, `Армавир` сочетается с отрицательным правилом `краснодар|кубан|krasnodar`.

Правило подавляет только совпадения связанной сущности. Если в записи одновременно есть `Армавир, Краснодарский край` и независимое упоминание `Армения`, сильное доказательство сохраняется.

Пустая строка означает отсутствие отрицательного правила.

### `source`

Происхождение термина. Несколько источников разделяются `;` без использования CSV-вложенности:

```text
rusources/arm_fullnames.csv;rusources/ru_surnames_arm.txt
```

Подробности и ограничения источников описаны в [`SOURCES.md` основного репозитория реестра](https://github.com/opendataam/armenian-keywords/blob/main/SOURCES.md).

### `review_status`

| Статус | Значение |
| --- | --- |
| `approved` | Запись проверена для заявленного способа сопоставления |
| `unverified` | Запись не подтверждена; в текущем реестре используется для слабых персональных признаков |
| `rejected` | Ошибочное или непригодное значение; сохраняется для аудита, но исключается из matcher и экспортов |

`approved` не означает универсальной истинности термина во всех коллекциях. Это решение о допустимости правила для текущего matcher и референсного источника.

Каждая `rejected`-запись обязана иметь `match_strength=weak`.

## Производное понятие `active`

`active` не хранится в CSV. Оно вычисляется так:

```text
active = review_status != rejected AND match_strength IN (strong, context_only)
```

Только active-записи образуют основной предфильтр. Слабые и отклонённые значения не дают автоматического включения.

## Примеры строк

Сильное правило:

```csv
place.armenia,армения,ru,Cyrl,geoname,армени(?:я|и|е|й|ю|ей|ею),strong,,manual/curated-v2,approved
```

Контекстное правило с отрицательным условием:

```csv
place.armavir,армавир,ru,Cyrl,geoname,армавир(?:а|у|ом|ем|е)?,context_only,краснодар|кубан|krasnodar,legacy/goskatalog,approved
```

Слабый непроверенный признак:

```csv
import.surname.0123456789ab,петросян,ru,Cyrl,surname,,weak,,rusources/arm_fullnames.csv,unverified
```

Отклонённый OCR-фрагмент, сохранённый для аудита:

```csv
legacy.keyword.0123456789ab,армениия,ru,Cyrl,keyword,,weak,,legacy/goskatalog,rejected
```

## Связь с языковыми CSV

В основном репозитории [opendataam/armenian-keywords](https://github.com/opendataam/armenian-keywords) файлы `data/{lang}/*.csv` генерируются из реестра и содержат только записи без статуса `rejected`. Сила правила, regex, источник и статус проверки сохраняются только в основном реестре, поэтому экспорты не должны использоваться как его полная замена. В этом репозитории хранится автономный снимок `data/terms.csv`, необходимый для воспроизведения извлечения.

## Проверка

```bash
python3 scripts/terms.py data/terms.csv
python3 -m pytest -q
```

Проверяются заголовок и порядок колонок, обязательные значения, перечисления, regex, запрет захватывающих групп, дубликаты активных значений и правило `rejected → weak`. Тесты также сверяют JSON Schema с константами валидатора.

После изменения локального снимка реестра необходимо повторить обе команды.
