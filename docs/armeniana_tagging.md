# Тематическая разметка «Армениана»

## Назначение и статус

Разметка относит подтверждённые записи `output/goskatalog/armenia_records.parquet` к темам, подтемам и персонам портала «Армениана». Это детерминированная автоматическая разметка версии `1.0.0`, а не результат экспертной атрибуции каждого предмета.

Входом могут быть только записи с `armenia_decision=include`. Файл `armenia_review.parquet` не обрабатывается и не должен использоваться как подтверждённое наполнение портала.

Текущая таксономия содержит:

- 5 тематических зон;
- 19 тем;
- 210 подтем;
- 13 персон, уже имеющих стабильные ID в исходном индексе.

Одна запись может относиться к нескольким зонам, темам и подтемам. Запись без совпадений получает статус `unclassified`; это не отдельная содержательная тема и не основание исключить запись из полного поиска.

## Текущий результат

- 58 291 входная запись, все исходные ID уникальны и сохранены;
- 54 691 запись (93,8%) имеет хотя бы одну тему;
- из них 43 017 (73,8% всех записей) имеют тему, подтверждённую содержанием записи, а 11 674 (20,0%) размечены только по типологии или профилю музея;
- 3 600 записей (6,2%) остаются `unclassified`;
- 119 982 присвоения темы или подтемы;
- 29 140 записей относятся более чем к одной теме;
- 8 757 записей связаны хотя бы с одной из 13 начальных персон;
- все 19 тем представлены, у каждого присвоения есть правила, поля и формы совпадения;
- 169 из 210 подтем получили хотя бы одну запись, 189 из 224 правил сработали хотя бы раз.

Доля размеченных записей сама по себе не характеризует качество тематической разметки: присвоение по типологии («Фотографии и негативы», «Документы») или по профилю музея говорит о виде предмета или собрания, а не о его сюжете. Поэтому `report.json` разделяет счётчики `content_tagged` и `structural_only`, а список правил второго типа приводит в `structural_rules`.

Актуальные распределения по зонам, темам, подтемам, персонам и правилам находятся в `output/armeniana/report.json`.

## Исходные реестры

| Файл | Назначение |
| --- | --- |
| `data/armeniana_themes.csv` | Зоны, темы и соответствие 14 темам Europeana |
| `data/armeniana_subthemes.csv` | Иерархия подтем |
| `data/armeniana_persons.csv` | Отображаемые имена и основная тема известных ID персон |
| `data/armeniana_tagging_rules.csv` | Правила присвоения тем и подтем |

ID зон, тем, подтем, персон и правил являются стабильными техническими идентификаторами. Их нельзя менять при редактировании отображаемых названий.

## Запуск

```bash
python3 scripts/tag_armeniana.py \
  --input output/goskatalog/armenia_records.parquet \
  --output-dir output/armeniana
```

Для небольших массивов можно изменить `--batch-size`. Пути к четырём реестрам задаются одноимёнными аргументами `--themes`, `--subthemes`, `--persons` и `--rules`.

Обработчик потоково читает входной Parquet, сохраняет все исходные поля, проверяет уникальность `id` и запрещает разметку записей со статусом, отличным от `include`. Реестр терминов `--terms` (по умолчанию `data/terms.csv`) нужен для подтверждения персон. Размер редакторской выборки задают `--audit-per-theme` (по умолчанию 30) и `--audit-unclassified` (по умолчанию 50).

## Выходные файлы

| Файл | Содержимое |
| --- | --- |
| `output/armeniana/records.parquet` | Все входные поля и шесть полей тематической разметки |

### Дополнительные поля `records.parquet`

| Поле | Тип | Значение |
| --- | --- | --- |
| `armeniana_zone_ids` | `list<string>` | ID всех зон записи без дубликатов |
| `armeniana_theme_ids` | `list<string>` | ID всех тем записи без дубликатов |
| `armeniana_subtheme_ids` | `list<string>` | ID всех подтем записи без дубликатов |
| `armeniana_person_ids` | `list<string>` | Известные ID персон из `armenia_matched_entities`, подтверждённые сильной формой имени |
| `armeniana_tagging_status` | `string` | `tagged` или `unclassified` |
| `armeniana_tagging_version` | `string` | Версия правил, сейчас `1.0.0` |

### Поля `assignments.parquet`

| Поле | Значение |
| --- | --- |
| `record_id` | ID записи в исходном массиве |
| `zone_id`, `theme_id`, `subtheme_id` | Присвоенная ветвь таксономии |
| `confidence` | Максимальная точность среди сработавших правил: `high`, `medium` или `low` |
| `rule_ids` | Все правила, подтверждающие это присвоение |
| `matched_fields` | Поля записи, в которых найдены основания |
| `matched_forms` | Нормализованные текстовые совпадения |
| `tagging_version` | Версия разметки |

`confidence` характеризует точность тематического правила, а не достоверность связи записи с армянским наследием: последняя уже определена предыдущим этапом извлечения.

## Формат правил

```csv
rule_id,theme_id,subtheme_id,fields,pattern,negative_pattern,confidence
```

- `fields`: `text`, `all` или конкретные поля через `|`.
- `text` включает название, описание, авторов, места, ключевые слова, происхождение, типологию, технику, фонд и период, но не музей и не ID персон.
- `all` дополнительно включает `museum.name` и `armenia_matched_entities`.
- `pattern` и `negative_pattern`: регулярные выражения после Unicode NFKC, case folding, замены `ё` на `е` и унификации тире. Нормализация не затрагивает escape-последовательности: `\W`, `\S`, `\D` и `\B` сохраняют свой смысл.
- Совпадения ограничиваются границами слов; разрешены только незахватывающие группы.
- `negative_pattern` подавляет правило в пределах выбранных полей записи.
- Правила по музею используются для тематически профильных собраний, например архитектурного, музыкального или театрального музея. Они имеют точность `medium`, потому что профиль музея не определяет сюжет конкретного предмета.
- Правила, ограниченные полями `typology.name` и `museum.name`, считаются структурными. Запись, у которой сработали только такие правила, учитывается в `structural_only`.
- Правило по полю `armenia_matched_entities` видит только подтверждённые персоны: сущность `person.*` сохраняется, если среди `armenia_matched_terms` есть её сильная форма (`match_strength=strong`). Отдельная фамилия, например «Хачатурян», относится к `context_only` и персону не подтверждает. По той же причине текстовые правила не содержат отдельных фамилий «хачатурян» и «туманян».
- Подтемы «Маринистика» и «Пейзаж и армянская художественная школа» присваиваются по имени Айвазовского или Сарьяна только вместе с морской или пейзажной лексикой в тексте записи. Портреты художника, издания о нём и документы выставок получают ID персоны, но не эти подтемы.

## Подсчёт статистики

Число записей в теме — это число уникальных `record_id`, а не число строк `assignments.parquet`. Одна запись может иметь несколько подтем внутри одной темы и поэтому должна учитываться в теме только один раз. По той же причине сумма тематических и зональных счётчиков больше числа записей.

## Контроль качества

1. Сверить `report.json`: сумма `tagged` и `unclassified` должна равняться числу входных записей.
2. Проверить, что каждое присвоение содержит хотя бы одно правило и поле совпадения.
3. Просмотреть `audit_sample.csv` по каждой теме и отдельно нерасклассифицированные записи. 30 записей на тему дают оценку точности с погрешностью около ±18 п. п.; для ±10 п. п. по теме нужно около 100 проверенных записей.
4. При системной ошибке исправить правило и повторить всю разметку; не редактировать только сгенерированный Parquet.
5. Ручные исправления на сайте хранить отдельно от автоматических присвоений, чтобы повторный импорт их не удалил.

## Ограничения версии 1.0.0

- Основная часть правил рассчитана на русскоязычные метаданные ГосКаталога.
- Регулярные выражения не заменяют содержательную экспертизу и не понимают изображения.
- Не все подтемы имеют правила: часть справочника предназначена для последующего пополнения и ручной курирования.
- Персоны ограничены 13 ID, распознанными предыдущим этапом. Отсутствие ID не означает отсутствие персоны в описании. В реестре терминов есть ещё `person.arshile_gorky`, но в справочник персон портала он пока не включён.
- Роль персоны (`автор`, `изображён`, `адресат` и т. п.) из исходных данных не восстанавливается.
- Автоматические присвоения не следует представлять как экспертно подтверждённые без отдельной проверки.
